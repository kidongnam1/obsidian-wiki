# PARA 프레임워크

파일을 확장자(.xlsx, .pdf, .hwp)별로 나누지 않고 **목적(프로젝트/영역)별**로 분류하는 지식 관리 체계.

## 왜 목적별 분류인가

- **맥락 유지 (Context Retention)**: 특정 사업 수행 시 확장자와 관계없이 관련 문서가 한 곳에 모여 있어야 즉시 의사결정 가능
- **지식의 완성도**: 엑셀(수치) + PDF(법률/도면) + HWP(공문) + 마크다운(요약)이 하나의 목적 아래 연결될 때 강력한 지식 네트워크 형성
- **뇌의 자연스러운 작동 방식**: "PDF 찾아야지"가 아니라 "광양 물류창고 서류 찾아야지"로 사고함

확장자별 분류는 창고에 도구를 망치끼리, 톱끼리 모아둔 것과 같다. 집을 지을 때(목적) 창고를 이리저리 뛰어다녀야 하므로 맥락이 끊기고 생산성이 떨어진다.

## 4개 분류 기준

| 폴더 | 목적 | 특성 |
|---|---|---|
| **01_Projects/** | 마감이 있는 명확한 사업 및 공사 프로젝트 | 시간 한정, 완료 시 Archive로 이동 |
| **02_Areas/** | 충전소, 물류, 자산관리 등 지속적 관리 영역 | 마감 없음, 지속적 책임 |
| **03_Resources/** | 참고 법규, 표준 양식, 연구 자료 | 관심사별 참고 자료 |
| **04_Archive/** | 완료된 옛 자료 보관 | 비활성, 검색용 보존 |

## 실제 폴더 구조 예시

```
My_Second_Brain/
├── 01_Projects/
│   ├── 2026_신축공사_설비/    # 엑셀, PDF, HWP, 허브노트 모두 포함
│   └── 2026_주주총회_제안/
├── 02_Areas/
│   ├── 서울_LPG충전소/        # 운영 규정, 장비 매뉴얼, 계약서
│   ├── GY_Logis_물류/
│   └── 자산관리_주식_XRP/
├── 03_Resources/
│   ├── 건축_소방법규_자료/
│   └── 세무_법률_표준서식/
└── 04_Archive/
    └── 2025_완료건/
```

## 하이브리드 2단계 분류 규칙

파일이 30개를 넘어가는 프로젝트 폴더 내부에서만 소분류를 적용:

- **대분류(루트)**: 무조건 목적(Project/Area)으로 폴더 생성
- **소분류(선택)**: 파일 30개 초과 시에만 프로젝트 폴더 내부에 `Attachments/` 하위 폴더로 원본 파일 정리
- **연결**: 마크다운 [[허브-노트-패턴|허브 노트]]에서 해당 파일들을 위키링크로 연결

## 핵심 원칙

- 하나의 파일은 하나의 분류에만 속한다
- 프로젝트가 완료되면 04_Archive로 이동한다
- 확장자가 아닌 **문맥(context)**이 분류 기준이다
